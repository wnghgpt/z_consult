# DB 적재 준비 (아직 원격 적용하지 않음)

사용자가 원격 `consult` 스키마를 생성했다고 확인했다. 마이그레이션은 기존 스키마를 사용하도록 `CREATE SCHEMA IF NOT EXISTS`로 변경했다. 테이블·함수·정책이 이미 생성된 경우에는 이 초기 마이그레이션을 재실행하지 말고 적용 상태를 먼저 확인한다. 스키마 생성만으로 테이블이나 Data API 노출 설정이 완료되는 것은 아니다.

## 확정 사항

- 원본 `No.`는 추출 시점이 달라도 유지되는 고객번호다. 정리본의 `번호`와는 동일시하지 않는다.
- 복수 상담·수술 칸은 눈/코/거상 등 여러 부위에 대응할 수 있다. 날짜 칸 수만으로 방문 수를 만들지 않는다.
- 동일 날짜·상태 두 칸도 원본에 보존한다. 칸과 부위별 대응이 불명확하면 개별 수술로 확정하지 않는다.
- 기존 앱 코드·환자·API를 공유하지 않는다. 같은 Supabase 인프라 내 `consult` 스키마에 5개 테이블만 생성한다.

## 이번 구현

- `supabase/migrations/202609300001_consult_core.sql`: 5개 테이블, 관계 제약, RLS, 원본 임시 적재 함수.
- `src/lib/importPlan.js`: 비교 계획만 생성하는 순수 함수. DB 쓰기를 수행하지 않는다.
- 업로드 화면에서 이전 엑셀을 비교용으로 읽고 신규/변경/동일 자료/확인 필요 후보와 근거를 표시한다.
- 이전 엑셀은 부분 목록이므로 미발견 고객을 신규로 확정하지 않는다. 전체 DB 조회가 구현되면 전체 목록 여부를 명시하여 판별한다.
- 수술·시술 자동 적재와 방문 병합은 아직 활성화하지 않았다. 원본에 방문번호가 없으면 명시적 검토 연결 또는 신규 방문 확정 과정이 필요하다.

## 5개 테이블

| 테이블 | 목적 |
| --- | --- |
| patients | 고정 고객번호, 기본정보, 공통 수동 메모 |
| consultations | 상담 건, 원본 스냅샷, 직접 입력 메모, 미예약 사유, 후속 연락 |
| procedures | 수술/시술 건, 부위 배열, 상담 연결, 원본 스냅샷 |
| photos | 비공개 파일 경로, 촬영 정보, 고객·수술 연결 |
| imports | 파일 해시, 추출 범위, 원본 임시 적재, 결과·변경 이력 JSON |

소유자까지 포함한 복합 외래키로 다른 사용자나 다른 고객의 상담·수술·사진 연결을 차단한다. 소유자별 데이터 격리이며 직원 공동 조회는 아직 설계하지 않았다. 사진 버킷과 Storage 정책은 사진 기능 단계에서 생성한다.

## 접근과 적용

1. 실제 Supabase 프로젝트를 식별하고 기존 스키마와 충돌 여부를 점검한다. 이 마이그레이션은 기존 스키마를 초기화하지 않는다.
2. 상담 앱을 사용할 계정에 서버 관리 `app_metadata.z_consult = true` 권한을 부여한다. 사용자가 수정할 수 있는 user_metadata를 권한 근거로 사용하지 않는다. 권한 변경 후 토큰 갱신이 필요하다.
3. 검토된 SQL을 적용하고 `consult`를 Data API 노출 스키마에 추가한다. 기존 노출 스키마는 제거하지 않는다.
4. React의 독립 인증 세션과 공개 클라이언트 설정을 연결한다. service_role/비밀 키를 브라우저에 넣지 않는다.
5. `stage_import`로 imports에 원본 후보를 임시 보관한다. 이것은 고객·상담 본 테이블 적재가 아니다.
6. 확정된 방문 연결과 최신성 검증, 충돌 재검증을 수행하는 트랜잭션 RPC를 추가한 후 본 테이블 저장을 활성화한다.

현재는 고객·상담·수술·사진 테이블에 클라이언트 쓰기 권한을 주지 않는다. 임시 적재도 앱 인증·권한 연결 전에는 UI에서 호출하지 않는다. 테스트/개발용 실제 환자 데이터를 저장소에 넣지 않는다.

## 임시 적재 제한 및 재시도

- 파일 SHA-256 + 시트 + 파서 버전 + 소유자를 고유키로 사용한다.
- 같은 입력의 재시도는 기존 imports ID를 반환한다. 같은 키인데 복원 결과가 다르면 오류다.
- 요청당 1~2,000개 고객 블록, JSON 5MiB로 제한한다. XLSX 파일 크기 제한과 별개다.
- 행 위치는 복원 증거일 뿐 방문 식별자로 사용하지 않는다.
- 원본 수정 시점이 없는 변경은 업로드 시각으로 최신이라고 판단하지 않는다.
- 본 테이블 저장 RPC를 구현하기 전에는 imports.changes로 되돌리기가 지원된다고 보지 않는다.

## 검증 결과

로컬의 독립 PostgreSQL 14에서 마이그레이션 실행, 동일 입력 재시도, 동일 해시의 다른 내용 거부, 소유자 간 조회 격리, 앱 권한 없는 계정 차단, 임상 테이블 직접 쓰기 차단을 합성 데이터로 검증했다. `tests/database.sql`은 빈 임시 DB 전용이며 실제 Supabase에서 실행하면 안 된다. Supabase Auth/Data API의 실제 통합 검증은 연결 이후에 진행한다.
